Part 2 · Lattice Cryptography

Hiding secrets in giant grids: the maths behind the main new standards.

2.1 Lattices: the grid that hides secrets

A lattice is a regular grid of points, like the holes in a pegboard or the atoms in a crystal. It is the foundation of ML-KEM, ML-DSA and FN-DSA.

Building a lattice from a basis

Pick two arrows, the basis vectors. Every lattice point is a whole-number combination of them: walk some whole number of steps along the first arrow and some along the second.

Example. Basis g₁ = (2, 0) and g₂ = (1, 2).
1·g₁ + 1·g₂ = (3, 2) is a lattice point. 2·g₁ − 1·g₂ = (3, −2) is too. But (2.5, 1) is not: it would need half-steps.

Same grid, different bases

The same lattice can be built from very different bases. b₁ = (7, 2) and b₂ = (5, 2) produce exactly the same points as g₁ and g₂: for example (7, 2) = 3g₁ + g₂, and (2, 0) = b₁ − b₂.

A good basisShort arrows, nearly at right angles. Easy to work with.
A bad basisLong arrows, nearly pointing the same way. Hides the grid's structure.

This is the trick of lattice cryptography: the private key is a good basis, and the public key is a bad basis of the same lattice.

The hard problems

Shortest Vector Problem (SVP)Find the lattice point closest to the origin (other than the origin itself).
Closest Vector Problem (CVP)Given any point in space, find the lattice point nearest to it.

In 2 dimensions you can solve these by eye. Cryptography uses lattices with hundreds of dimensions, where the number of nearby points to check grows exponentially. The best known algorithms, quantum included, would take longer than the age of the universe.

Worked example: SVP. With the good basis g₁ = (2, 0), g₂ = (1, 2), the short vectors are easy to see: g₁ has length 2, g₂ has length √5 ≈ 2.24. The shortest non-zero lattice vector is ±(2, 0).
The bad basis b₁ = (7, 2), b₂ = (5, 2) makes the same lattice, but its arrows have lengths 7.28 and 5.39. The short vector is hidden: you only find it by spotting the combination b₁ − b₂ = (7 − 5, 2 − 2) = (2, 0). In 500 dimensions, finding such a combination is hopeless.
Worked example: CVP with each basis. Target t = (4.4, 1.3). The simple method: write t in terms of the basis, then round to whole numbers.
Good basis: t = 1.875·g₁ + 0.65·g₂ → round to 2·g₁ + 1·g₂ = (5, 2), distance 0.92. This is the true closest point. ✓
Bad basis: t = 0.575·b₁ + 0.075·b₂ → round to 1·b₁ + 0·b₂ = (7, 2), distance 2.69. Wrong! ✗

With the good basis, rounding works. With the bad basis it fails, and in hundreds of dimensions nobody knows how to fix it.

2.2 Learning with errors (LWE): equations with a little noise

ML-KEM and ML-DSA are built on a puzzle called Learning With Errors (Oded Regev, 2005). It turns the lattice problem into simple sums with a small amount of deliberate noise.

Easy without noise

Suppose there is a secret pair s = (s₁, s₂), and you are given sums on a 17-clock (mod 17):

4·s₁ + 1·s₂ = 0 (mod 17)
7·s₁ + 3·s₂ = 2 (mod 17)

Two equations, two unknowns: school algebra (Gaussian elimination) solves them at once. The answer is s = (3, 5). Check: 4·3 + 5 = 17 → 0 ✓, and 7·3 + 3·5 = 36 → 2 ✓.

Hard with a little noise

Now add a tiny random error e (−1, 0 or +1) to each answer before publishing it:

Rowaa·s mod 17error ePublished b
1(4, 1)0+11
2(7, 3)2−11
3(2, 8)12012
4(5, 6)11+112

The public sees only the a's and b's. Now elimination breaks down: every step mixes and grows the hidden errors until the answer is garbage. With hundreds of unknowns and well-chosen noise, finding s is as hard as solving a lattice problem. That is the LWE problem.

Why lattices? The rows a, together with the clock, define a lattice; the true values a·s are a lattice point, and the noisy b's are a point near it. Removing the noise means solving CVP (2.1).

Encrypting one bit with LWE

Here is a complete toy version of Regev's encryption, using the table above. Private key: s = (3, 5). Public key: the four rows (a, b).

Encrypt. Alice secretly picks some rows, say rows 1, 3 and 4, and adds them up:

u = (4+2+5, 1+8+6) = (11, 15) (mod 17), and v = 1 + 12 + 12 = 25 → 8 (mod 17).

To send bit 0 she sends (u, v = 8). To send bit 1 she adds "half the clock" (8) to v: (u, v = 16).

Decrypt. Bob computes u·s = 11·3 + 15·5 = 108 → 6 (mod 17), then v − 6:

Bit 0: 8 − 6 = 2, close to 0, so the bit is 0. ✓
Bit 1: 16 − 6 = 10, close to 8 (half the clock), so the bit is 1. ✓

The leftover 2 is exactly the sum of the chosen errors: +1 + 0 + 1. It is small, so it doesn't spoil the answer.

Picture the 17-clock: results in the top half (near 0) decode as 0, results in the bottom half (near 8) as 1. Our two results, 2 and 10, are marked. The noise nudges the result a little but, as long as the total noise stays small, never across the border.

2.3 ML-KEM (Kyber): the new key exchange

ML-KEM (formerly CRYSTALS-Kyber) is the main post-quantum key exchange, standardized as FIPS 203 in 2024 and already used by major browsers. It is LWE (2.2) made fast and compact.

Numbers become polynomials

Plain LWE needs huge tables of numbers. ML-KEM packs 256 numbers into one polynomial: an expression like 3 + 5x + 2x² + … + 7x²⁵⁵, where each coefficient is a number on a clock of size q = 3329.

Polynomials are multiplied as usual, with one wrap-around rule: x²⁵⁶ = −1. So the result never grows past x²⁵⁵. Here is the same rule on a small scale, with x⁴ = −1:

(x³ + 2) · (x + 1) = x⁴ + x³ + 2x + 2. Replace x⁴ by −1: −1 + x³ + 2x + 2 = x³ + 2x + 1.

One polynomial multiplication does the work of a whole 256 × 256 table, and a clever shortcut (the number-theoretic transform, a fast way to multiply polynomials using clock arithmetic) makes it very fast.

Small blocks called modules

Instead of one giant polynomial, ML-KEM uses a small k × k grid of them, called a module. Changing k changes the security level:

How a key exchange runs

It follows the toy encryption from 2.2 exactly, with polynomials in place of numbers:

  1. KeyGen (Bob): picks a small secret s and small noise e, publishes the public key (A, t = A·s + e). A is a grid of random polynomials, made from a short seed so it doesn't need to be sent in full.
  2. Encaps (Alice): picks a random 32-byte message m, uses fresh small r, e₁, e₂ and computes u = Aᵀ·r + e₁ and v = tᵀ·r + e₂ + m·(q/2), just like adding "half the clock". She sends (u, v) and derives the shared key K from m with a hash.
  3. Decaps (Bob): computes v − sᵀ·u, which is m·(q/2) plus small noise, rounds each coefficient to 0 or q/2 to recover m, and derives the same K.
A safety check (the Fujisaki–Okamoto transform). After decrypting, Bob re-encrypts m himself and checks that he gets exactly the same ciphertext. If a forged ciphertext is detected, he returns a useless random key. This blocks attackers who send trick ciphertexts to learn about s.

Speed and size

ML-KEM is faster than RSA and elliptic curves: generating keys and exchanging a secret takes a fraction of a millisecond. Its only cost is size: about 1 KB each way, against 32 bytes for elliptic curves. Bigger, but still tiny next to a typical web page.

2.4 Lattice signatures: ML-DSA and FN-DSA

Signatures use the same lattice ideas. The challenge: show you know the secret without the signature leaking it.

Signatures in three steps

1. CommitThe signer picks a random "mask" y and publishes a fingerprint w of it.
2. ChallengeA hash of the message and w produces a small challenge c, which nobody can predict or choose.
3. RespondThe signer sends z = y + c·s. The mask y hides the secret s.

The verifier checks the answer using only public values. This recipe is called Fiat–Shamir, after the people who showed how a hash can replace a live questioner.

Toy example with numbers

Clock q = 97, public number a = 10. Private key s = 3. Public key t = a·s = 30.

Commit: random mask y = −5, so w = a·y = −50 → 47 (mod 97).

Challenge: the hash of (message, 47) gives c = 2.

Respond: z = y + c·s = −5 + 2·3 = 1. The signature is (c = 2, z = 1).

Verify: a·z − c·t = 10·1 − 2·30 = −50 → 47 = w ✓. The verifier rebuilds w, re-hashes, and gets the same c.

(In this toy, s could be found by dividing 30 by 10. In real ML-DSA, s is a short vector of polynomials and t = A·s + e is an LWE sample, so it can't be undone.)

Rejection, or "with aborts"

If z = y + c·s comes out unusually large, it could hint at s (a big z suggests a big s pushed it there). So the signer throws it away and tries again with a new mask. Only signatures inside a safe range are published.

With s = 3 and c = 2, only z between −4 and 4 is published. Mask y = −5 gives z = 1: accept. Mask y = 8 gives z = 14: too big, reject and retry. On average ML-DSA needs a handful of tries per signature, which is still very fast.

This idea is called Fiat–Shamir with aborts (Vadim Lyubashevsky), and it is the heart of ML-DSA.

Its signatures are much smaller, but it needs careful floating-point maths (the fast Fourier transform) to avoid leaking secrets.
