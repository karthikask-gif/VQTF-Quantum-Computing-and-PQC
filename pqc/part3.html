Part 3 · Other Families

Hash-based, code-based, multivariate and isogeny cryptography.

3.1 Hash-based signatures: security from fingerprints alone

If you trust nothing else, you can still trust a good hash function. Hash-based signatures rely only on that, which makes them the most conservative choice.

Hash functions

A hash function turns any input into a short fixed-size fingerprint. Real ones such as SHA-256 have three properties:

Easy forwardComputing H(x) is fast.
One-wayGiven a fingerprint, you can't find an input that produces it.
Collision-resistantYou can't find two inputs with the same fingerprint.

For the numbers below we use a toy hash, H(x) = (x² + 7) mod 101. It is far too small to be secure, but it shows the mechanics.

Lamport one-time signature

Leslie Lamport's 1979 idea: for each message bit, prepare two secret numbers (one for "0", one for "1") and publish their hashes.

Private key (2-bit messages): bit 1: (17, 42), bit 2: (63, 88).

Public key = hashes: H(17) = 94, H(42) = 54, H(63) = 37, H(88) = 75 → (94, 54), (37, 75).

Sign the message 10: bit 1 is 1, so reveal 42; bit 2 is 0, so reveal 63. Signature = (42, 63).

Verify: H(42) = 1764 + 7 = 1771 → 54 ✓ (bit 1's "1" slot). H(63) = 3976 → 37 ✓ (bit 2's "0" slot).

Forging "11" would need a number that hashes to 75. That means reversing the hash, which is impossible for a real hash.

Only once! After signing 10 and then 01, all four secrets are public and anyone can sign anything. That is why it is a one-time signature.

Shorter signatures with hash chains

Lamport signatures are large. Winternitz signatures sign several bits at once using a chain: hash the secret again and again.

Secret 5. Chain: 5 → H → 32 → H → 21 → H → 44. Public key = 44 (the end of the chain).

Sign the digit 1: reveal the value after 1 hash, 32.

Verify: hash 32 two more times: 32 → 21 → 44 ✓ (1 + 2 = 3 steps in total).

Anyone can walk forward along the chain, so a checksum digit is added to stop forgers from turning a 1 into a 2.

Merkle trees

One-time keys are awkward: you would need a new public key for every message. Ralph Merkle's fix: make many one-time key pairs, hash their public keys together in pairs, and keep hashing up to a single root. Only the root is published.

Pair-hash rule (toy): H₂(x, y) = (3x + y) mod 101.

H₂(94, 37) = 319 → 16; H₂(12, 60) = 96 → 96; root = H₂(16, 96) = 144 → 43.

Signing with leaf 2 (37): send the one-time signature, the leaf 37, and its authentication path: the neighbours 94 and 96 (dashed orange).

Verify: H₂(94, 37) = 16, then H₂(16, 96) = 43 = root ✓.

A tree of height h holds 2ʰ one-time keys, and each signature needs only h neighbours. XMSS and LMS are standardized versions; they are stateful: the signer must remember which leaves are used, because reusing one is fatal.

SLH-DSA (SPHINCS+): no memory needed

SLH-DSA removes the state by using a huge tree of trees (a "hypertree") and picking the leaf from a hash of the message, so the same leaf is practically never chosen twice. It also uses a few-time signature (FORS) at the bottom.

StrengthsSecurity rests only on hash functions, the best-understood tools in cryptography. Public key just 32 bytes.
CostsSignatures of 7,856 bytes (small, slow version) to 17,088 bytes (fast version) at level 1, and signing is slower than ML-DSA.

3.2 Code-based cryptography: hiding messages in errors

Phones, Wi-Fi and spacecraft all use error-correcting codes to repair bits damaged in transit. Robert McEliece realized in 1978 that this repair skill can be a secret key.

The Hamming(7,4) code

Richard Hamming's code turns 4 data bits into 7 by adding 3 parity checks (a parity bit says whether a group of bits holds an even or odd number of 1s), so that any single flipped bit can be found and fixed. Positions 1, 2 and 4 hold checks; positions 3, 5, 6 and 7 hold data.

Encode data 1011 (d₁ = 1, d₂ = 0, d₃ = 1, d₄ = 1):

p₁ = d₁ ⊕ d₂ ⊕ d₄ = 0, p₂ = d₁ ⊕ d₃ ⊕ d₄ = 1, p₃ = d₂ ⊕ d₃ ⊕ d₄ = 0.

Codeword (positions 1–7: p₁ p₂ d₁ p₃ d₂ d₃ d₄) = 0110011.

Noise flips position 6: received 0110001.

Decode: check positions {1,3,5,7}: 0⊕1⊕0⊕1 = 0. Check {2,3,6,7}: 1⊕1⊕0⊕1 = 1. Check {4,5,6,7}: 0⊕0⊕0⊕1 = 1. Read the checks bottom-up as binary: 110 = 6. Flip position 6 back. ✓

Syndrome decoding, the hard problem

The three check results form the syndrome. In Hamming's code the checks are arranged so the syndrome spells out the error's position in binary (110 = 6 above). That is the "hidden structure" that makes decoding instant.

Now scramble the checks so they look random. The syndrome still exists, but it no longer points anywhere. To find the errors, Eve must try combinations of positions until the checks match. That is the syndrome decoding problem.

Clever algorithms do better than trying everything, but for McEliece's sizes they still need around 2¹²⁸ steps, and quantum computers give only a modest (Grover-like) speed-up.

McEliece, errors as a lock

For small codes, anyone can decode. But for a huge, randomly scrambled code, decoding is extremely hard unless you know the hidden structure:

  1. Private key: a large code with a fast decoder (a "Goppa code" that can fix t errors), plus secret scrambling.
  2. Public key: the scrambled code, which looks completely random.
  3. Encrypt: turn the message into a codeword of the public code, then deliberately flip t random bits.
  4. Decrypt: unscramble and use the fast decoder to remove the errors. Without the secret structure, Eve faces general decoding, a problem that has stayed hard for over 45 years.
Classic McElieceVery well studied. Tiny ciphertexts (about 100 bytes) but enormous public keys: about 261 KB at level 1, over 1 MB at level 5.
HQCChosen by NIST in 2025 as a backup to ML-KEM, so that a surprise attack on lattices wouldn't leave the world without a standard. Keys and ciphertexts of a few KB.

3.3 Multivariate and isogeny cryptography

Two more families round out the picture: one built on systems of equations, one on elliptic curves. Both have taught important lessons.

Multivariate equations

Solving one equation with one unknown is easy. Solving many quadratic equations (with terms like x₁·x₂) in many unknowns at once is very hard, even with bits only.

Toy public key (bits, mod 2): P₁ = x₁x₂ + x₃ and P₂ = x₂x₃ + x₁.

Sign the message (1, 1): find bits x with P₁ = 1 and P₂ = 1. The signer, who knows a hidden shortcut, gives x = (1, 1, 0).

Verify: P₁ = 1·1 + 0 = 1 ✓, P₂ = 1·0 + 1 = 1 ✓. Checking is just plugging in.

With 3 variables you could try all 8 options. Real schemes use around 100 variables: 2¹⁰⁰ options.

The MQ problem, trying every answer

Finding bits that solve such equations is the MQ problem (multivariate quadratic). With 3 bits, Eve can try all 2³ = 8 options:

Three answers work, and any one is a valid signature. Each extra variable doubles the table: 100 variables give 2¹⁰⁰ rows, far beyond any computer.

The oil-and-vinegar shortcut

The signer's equations secretly have two kinds of variables, oil (o) and vinegar (v), and never multiply oil by oil. Fixing the vinegar turns every equation into an easy linear one.

Example (mod 11): solve 3·o·v + v² + o = 2.

Pick vinegar v = 2: 6o + 4 + o = 2, so 7o = 2 − 4 = −2 = 9 (mod 11).

Divide by 7, which mod 11 means multiply by 8 (since 7 × 8 = 56 = 55 + 1): o = 9 × 8 = 72 mod 11 = 6.

Check: 3·6·2 + 2² + 6 = 36 + 4 + 6 = 46 = 44 + 2, so 46 mod 11 = 2 ✓.

The signer's shortcut is a secret, easy-to-solve system disguised by scrambling the variables. Schemes such as UOV ("unbalanced oil and vinegar") have short signatures but large public keys. Rainbow, a 2020 NIST finalist, was broken in 2022 by a weekend's computing on a laptop, a reminder that new schemes need years of testing.

Isogenies

An isogeny is a special map from one elliptic curve (1.2) to another. Picture a vast network of curves connected by such maps: walking a random path is easy, but finding a path between two given curves seems very hard, even for quantum computers.

Isogeny schemes have the smallest keys of all. But the most famous one, SIKE, was broken in 2022 with a classical attack that took about an hour on a single computer, because its public keys revealed extra information. Newer designs such as SQIsign (very compact signatures) avoid that weakness and are still being studied.

Lesson: a scheme isn't trusted just because quantum computers can't break it. It must also survive years of classical attack. That is why NIST picked lattices plus backups from different families.
